# Signal sources

Call signals_sources and signals_resources to discover connected sources and their real fields. Direct PostHog connections, imports and routines are disabled; preserve their stored data and create a new o11 routine for ongoing use. Product database is a direct PostgreSQL connection; chat history is content in a source, not a separate connector. o11 tracking provides explicitly instrumented business events and approved text; @o11/tracking/replay provides native session replay. New routine setup uses o11 events and the o11 replay pipeline when recording evidence is needed, sharing existing PostHog replay or using native capture otherwise. Reuse the application capture lifecycle across routines; event-only setup does not require replay. Read the replay guide for code-level PostHog sharing through the explicit posthog option, its tested versions and release requirements. Preserve existing PostHog recording settings and delivery; never silently start another recorder. Stored legacy evidence retains its provenance; direct PostHog imports and live routines are disabled. Keep existing analytics SDKs for their other uses. Read source availability and capabilities before choosing evidence. A bounded event catalog helps map existing handlers; it cannot prove that an unseen event does not exist. Other analytics already present in the application should be inspected for reuse; this does not imply a supported direct connector.

Use recorded activity and coverage for inactivity. Direct customer database scans are unavailable.

Active published definitions support all/any/ordered steps, customer/session/account/subject scope, bounded windows, per-step counts, distinct items, missing actions and verified cross-source identity. Each step can include semantic {textProperty, criterion}; repetitions counts whole ordered workflows. OpenAI Decisions screens meaning, and a separate check cites actual records. Read the signals guide for exact behavior and limits. Missing properties, general joins, arbitrary SQL and unsupported sources must be reported, not silently inferred. Fetch current validation and readiness: documentation examples are not proof a worker is deployed.

Within a source, stable customer identity links sessions. Across sources, identities are namespaced and require explicit verified links, even when external IDs match. Similar names or emails are not enough. Missing events and incomplete history remain unconfirmed.
