# Verify historical behavior

Use only the connected o11 MCP endpoint or CLI. o11 reads its configured sources on the server. A coding agent does not need a separate PostHog connection, provider login or analytics credential. Inspect each tool's current schema with o11 tools describe before calling it. If a required tool is unavailable, report the missing o11 capability or permission; do not switch to a provider connector.

Use one short sentence per summary or limitation; give blockers one next action. Keep diagnostics under Details.
For new o11 tracking without verified earlier history, say "Checks events o11 has received since setup." Claim earlier events only after verifying receipt or import.

Investigate o11 event receipts, coverage and recordings. Direct PostHog connections and imports are disabled, including existing sources. Preserve saved data and definitions; do not attempt provider authorization or import controls. Missing historical o11 coverage cannot be reconstructed by installing tracking today.

Start with o11_setup, organization_current, engagement_capabilities, signals_sources and analytics_status. Verify the workspace, source ID, environment, granted scopes and import progress. Reuse returned IDs. Query independent discovery calls together and retain their results for this investigation. Recheck state after configuration changes.

For counts, order and first-session rules, start with recorded events. Discover the action and session fields with signals_resources and signals_sample. Build the exact structured definition, call signals_check, then signals_previewEvents. A preview can run without saving or activating a routine. Set imported only when inspecting the imported corpus; a source preview and an imported preview can have different coverage. Inspect findingPage and pendingPage for total, returned and nextOffset. Page findings with findingOffset and findingLimit; page pending absence checks independently with pendingOffset and pendingLimit. Retain the returned previewAsOf and previewFingerprint for either cursor, and use a new mutation operation ID for each distinct page input. Follow both cursors when the investigation needs all findings and pending checks. An oversized evidence record or coverage summary produces an explicit refusal; narrow the preview window or source scope before a new preview, and keep that investigation unverified until evidence is available. o11 rejects paging when late data changes the evidence. Display pagination preserves the full scan complete/coverage result. Follow returned pagination and inspect complete, reason and coverage fields. An empty or truncated preview cannot establish absence. The preview window selects candidates; it must not define the start of a customer's history.

When historical coverage blocks setup, inspect the selected o11 source, receipt status, continuous coverage and actual application delivery. Identify the missing evidence and the owner’s next action. Do not claim complete history from an empty sample or reconstruct earlier activity with a new SDK installation.

An event preview is observational and does not enroll customers or send messages. After a timeout, inspect o11_operation_status; when its recovery permits a fresh signals.previewEvents call, use a new operation ID and restart from the first page. A running or uncertain preview receipt is not evidence of no matches. This recovery applies only to the named preview; retain the existing receipt and reconciliation protections for publication, activation and delivery.

For “five messages in the first Excel session,” count unique message events in one session. Determine the earliest Excel session from all recorded Excel activity, including sessions with zero messages, then check its message count. A first web session does not establish the first Excel session. Keep source identity, verified customer identity links and session IDs distinct. Exclude later sessions, counts spread across sessions, missing identities, ambiguous ordering and incomplete imports. Source history proves only retained recorded activity; it cannot recover erased recordings or activity that was never captured. Verify the deployed schema supports the first-session condition; a history query used during setup is not a live monitoring rule.

Use research_sessions to inspect recording metadata and research_customer to follow the customer's earlier sessions. Use research_recordingDetail, research_recordingActivity, research_history and research_report for saved evidence and prior analysis. Follow their cursors and report pages when the claim requires them. A recording list does not count messages or prove complete event history. Use recording evidence when the behavior cannot be established from events, or to inspect a discrepancy. Existing archived evidence can be read through o11_read_artifact; respect its size limit and use paginated reports for larger artifacts. Do not download recordings or run a model over every recording to count structured events. Archive preparation is a separate mutation; request it only when needed and authorized. Historical analysis tools that can send owner previews or execute contact actions require separate authorization. Reading existing evidence and event previews does not send messages.

Verify both matches and exclusions: a qualifying first session, a first session below the threshold followed by a qualifying later session, a zero-message first session, and counts split across sessions. Use real available evidence. If an example is unavailable, record that check as unverified; never invent customers or test data. Distinguish historical preview, current source validation and deployment readiness in the setup report. A valid draft does not prove monitoring is running. Preserve the same routine ID and request, save the returned revision, and read it back before reporting completion.
