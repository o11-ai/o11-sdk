# CLI and MCP

Run **o11 update --check --json** to compare with the server’s advertised release. **o11 update** verifies and installs a newer release or repairs the same release; older metadata never causes a downgrade. Bun global installs update in place. Other installs stage an isolated verified replacement and return the command to use, preserving the original installation. On version, command, or schema disagreements, inspect live schemas, attempt a verified update, and retry with the returned command before reporting a blocker. **o11 --version --json** reports the executable checksum. Restart MCP bridges after updating. Credentials are preserved. Update failures do not block normal commands.

Install @o11/cli@0.2.5. Run **o11 login --server https://YOUR_API** once, then **o11 status**. Use --profile NAME to keep workspace credentials separate. Login supports browser OAuth with PKCE; tokens are stored in the OS credential store. Check **o11 --help** for headless options before using them. In supported builds on POSIX hosts, **--credential-store file** explicitly selects private local credential files; the saved profile remembers that choice. **--no-browser** prints the sign-in link without launching a browser. If these options are absent, use the OS keyring or upgrade when a supported release is published. For a VM or remote terminal, check **o11 --help** for **login --input FILE|-**. In a supported build, run **o11 login --no-browser** and keep that process alive. After browser approval, copy the sign-in code and paste it into the coding agent. Submit the code on the same remote host using **o11 login --input FILE|-**; use a private file and delete it after submission. The waiting login process verifies state, exchanges the code with PKCE and saves the credentials. The code expires and works once. Approval alone does not confirm the connection: check **o11 status**. If the waiting process expired, restart login and get a new code. Older CLI builds require an upgrade or port forwarding, for example **ssh -L 49191:127.0.0.1:49191 YOUR_HOST**, before starting login. For unattended jobs, an organization owner can provision a scoped service key with a 1–365 day expiry. Set O11_TOKEN_FILE to its private regular file (mode 0600 on POSIX); symlinks and files readable by other users are rejected. O11_TOKEN is also supported, but cannot be combined with O11_TOKEN_FILE. Set O11_SERVER to the intended server, then run o11 status --json and check workspace, scopes and expiry. Keep keys out of command arguments, logs and committed files. To rotate, provision a replacement, verify it against the same workspace, then revoke the old key. Revocation and membership removal take effect on subsequent requests. Initial provisioning and permission increases require owner consent.

Use analytics_previewImport to validate a recent import page without saving customer records or triggering analysis. It reads a one- or two-hour window, returns counts and a bounded schema sample, and provides an expiring cursor. Its mode is preview_only and stored is false. It does not satisfy a history-import requirement.

For up to 500 selected recordings, research_analyzeSelectedOnly uses configuration permission and guarantees no customer or owner messages. It persists a requestId and returns runId, queued and busy IDs, per-item dispatch state and a progress call. Poll research_selectedProgress with only the queued IDs; it reports running/completed/failed/blocked and per-session results. Queue publication failure leaves a durable dispatch_pending item for worker recovery. Retry busy IDs using the supplied continuation after their existing work finishes. research_pauseSelectedOnly and research_resumeSelectedOnly control the exact no-send run in either environment. Active leases remain unchanged; retry after the reported lease deadline. Resume preserves checkpoints and retry deadlines. Owner previews use the separate research_analyzeSelected command with delivery permission. A successful submission proves acceptance; completion and detection quality require separate checks.

The CLI coordinates token refresh across commands and local MCP bridges using the same profile and credential store. Upgrade every process sharing that profile. A busy credential store fails after 30 seconds; retry after the other command finishes. Refresh requests time out after 20 seconds, and a terminated owner can be recovered automatically. A live owner is never evicted merely because its lock is old. Normal login verifies and reuses the existing grant, including automatic refresh. New routine prompts do not require sign-in again. Use **o11 login --reauth** for an explicitly requested fresh sign-in. Additional scopes still require consent. Network failures retain the saved login and should be retried rather than treated as logout. New server grants use a finite 100-year refresh lifetime, renewed on rotation; old grants retain their original expiry until refreshed or reauthorized. Revocation and lost workspace membership still deny access.

**o11 docs** is the CLI's bundled documentation snapshot. After connecting, read the current server documentation with **o11 call o11_docs --input FILE**, where FILE contains `{"page":"tracking"}` (or another returned page ID). Use the server's SDK version and tool schemas when its documentation is newer than the installed CLI.

- o11 commands [--search TEXT] — list readable commands.
- o11 routines get --id ID — read a routine; --help shows fields and --json returns machine-readable output.
- o11 tracking status --environment test — inspect tracking.
- o11 docs PAGE --live — read current server documentation.
- o11 operations status --id UUID — inspect a write before retrying.
- o11 operation-id — generate a UUID to supply with --operation-id for writes.
- o11 tools list [--search TEXT] — compatibility alias for command discovery.
- o11 tools describe TOOL — retrieve the current input schema.
- o11 call TOOL --input FILE — execute a tool; use - for standard input.
- o11 docs [PAGE] — read bundled versioned setup documentation without authentication.
- o11 mcp — expose the same server tools over local stdio.
- o11 logout — delete locally stored credentials; revoke agent access in o11 to invalidate the grant remotely.

CLI commands use plain HTTP JSON requests at /api/agent/v1, with no MCP handshake or streaming connection. Human terminals show readable results; --json or redirected output returns JSON. Errors go to stderr and exit nonzero. The OAuth sign-in helpers and protected resource are shared with MCP for existing-grant compatibility; only o11 mcp opens an MCP connection. Credential calls should use --output-file PATH to reserve a private file before dispatch and keep secrets out of agent transcripts. An existing destination is never overwritten. An empty file after a transport error is not proof that a mutation failed; inspect the operation receipt before retrying. Supply --operation-id UUID (or _operationId in the input file) on every mutation and preserve it with identical input for retries. A timeout leaves the outcome uncertain: inspect o11_operation_status and the affected record before doing anything again. Remote MCP and CLI may authenticate as different grants; operation recovery must remain scoped to the same authorizing user and workspace. Never generate a new ID to repeat an uncertain action.

Configuration, credentials, publication and sending have separate permissions. Scope failures require consent for that permission, not a different endpoint. All tools retain membership, ownership, revision and provider checks. Provider passwords, 2FA and OAuth consent are completed by the account owner.
